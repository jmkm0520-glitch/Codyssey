# 국내 여행 추천 API 연동 프로그램

## 1. 미션 소개

Python에서 LLM API와 지도·장소 검색 API를 연동해 국내 여행 추천 프로그램을 개발한다.

사용자가 여행 날짜를 입력하면 프로그램은 다음 과정을 수행한다.

1. LLM이 해당 시기에 여행하기 좋은 국내 지역을 추천한다.
2. 추천 지역을 지도·장소 검색 API에 전달해 맛집을 검색한다.
3. 추천 정보와 맛집 검색 결과를 조합해 최종 여행 리포트를 생성한다.

이번 미션의 핵심은 단일 API 호출이 아니라 여러 API의 결과를 구조화하고, 다음 단계의 입력으로 연결해 하나의 인사이트를 만드는 것이다.

## 2. 최종 결과물

다음 결과물을 포함한 프로그램 1개를 완성한다.

### CLI 기반 Python 프로그램

- Python 3.10 이상
- `argparse` 사용
- 필수 옵션: `--date "YYYY-MM-DD"` 또는 `-date "YYYY-MM-DD"`
- 실행 중 단계별 진행 로그 출력
- 완료 후 결과 저장 경로 안내

실행 예시:

```bash
python travel_planner.py --date "20XX-03-15"
```

### 실행 결과 데이터

`results/` 폴더에 다음 파일을 생성한다.

- 원본 데이터 JSON 1개 이상
  - 1차 여행 추천 결과
  - 맛집 검색 결과
  - 오류 목록
- 최종 여행 리포트 Markdown 1개

### README.md

다음 내용을 포함한다.

- 프로그램 개요
- 설치 및 실행 방법
- API 키 설정 방법
- 결과물 확인 방법
- API 키 유출 방지 주의 사항

## 3. 학습 목표

과제를 마친 후 다음 내용을 설명할 수 있어야 한다.

- REST API의 요청·응답 구조와 `GET`, `POST`의 차이
- LLM 출력을 JSON으로 구조화해 다음 API의 입력으로 사용하는 흐름
- 인증, 쿼터, 네트워크, 파싱 등 외부 API의 대표 오류와 대응 원칙
- API 키를 코드에 작성하지 않고 `.env` 또는 환경변수로 관리하는 이유

## 4. 기능 요구사항

### 4.1 CLI 인터페이스

- `argparse`로 실행할 수 있어야 한다.
- 여행 날짜는 필수 입력값이다.
- 날짜 형식이 `YYYY-MM-DD`가 아니거나 존재하지 않는 날짜이면 사용법을 출력하고 종료한다.

### 4.2 API 제공자

LLM API는 다음 중 하나를 선택한다.

- OpenAI 계열 API
- Google Gemini 계열 API

지도·장소 검색 API는 다음 중 하나를 선택한다.

- Kakao Local API
- Naver Local Search API
- 아래 공통 조건을 만족하는 다른 API

다른 장소 검색 API를 사용할 경우 다음 조건을 만족해야 한다.

- 국내 장소 검색이 가능해야 한다.
- 응답을 JSON으로 받을 수 있어야 한다.
- `place_name`, `address`, `lat`, `lng`, `url` 또는 이에 준하는 값을 제공해야 한다.

### 4.3 LLM 여행지 추천

사용자가 입력한 날짜를 LLM에 전달하고, 반드시 JSON으로 파싱 가능한 결과를 받도록 프롬프트를 설계한다.

1차 추천 JSON의 최소 스키마:

```json
{
  "recommended_city": "제주",
  "weather": "3월 중순 평균 15°C 내외로 비교적 온화함",
  "events": ["유채꽃 관련 지역 행사", "봄 시즌 지역 축제"],
  "reason": "3월 중순은 봄꽃을 즐기기 좋은 시기입니다. 야외 활동에도 비교적 적합합니다."
}
```

필수 필드:

| 필드 | 타입 | 설명 |
| --- | --- | --- |
| `recommended_city` | string | 추천 국내 도시 또는 지역 |
| `weather` | string | 해당 시기의 일반적인 날씨 요약 |
| `events` | array of string | 행사·축제 후보 1~3개 |
| `reason` | string | 추천 근거 2~4문장 |

실제 날씨와 행사 정보의 정확도보다 구조화된 출력과 다음 단계로의 연결을 중점적으로 평가한다.

### 4.4 맛집 검색

- 1차 추천 JSON의 `recommended_city`를 검색어로 사용한다.
- 해당 지역의 맛집을 권장 5곳 검색한다.
- 검색 결과가 0건이어도 프로그램을 중단하지 않는다.
- 0건이면 맛집 데이터를 빈 목록으로 저장하고 리포트 생성을 계속한다.

맛집 데이터의 최소 필드:

| 필드 | 타입 | 필수 여부 |
| --- | --- | --- |
| `name` | string | 필수 |
| `address` | string | 필수 |
| `category` | string | 가능한 경우 |
| `url` | string | 가능한 경우 |
| `x`, `y` 또는 `lat`, `lng` | number | 가능한 경우 |

인증 방식 예시:

- Kakao Local: 인증 헤더에 API 키를 전달한다.
- Naver Local Search: 클라이언트 ID와 Secret을 헤더로 전달한다.
- `401` 또는 `403` 발생 시 키, 헤더명, 권한 및 서비스 설정을 확인한다.

### 4.5 최종 여행 리포트 생성

1차 추천 JSON과 맛집 목록을 LLM에 전달해 Markdown 리포트를 생성한다.

리포트에는 다음 항목을 포함한다.

```markdown
# YYYY-MM-DD 국내 여행 추천 리포트

## 추천 지역
## 추천 이유
## 날씨 요약
## 행사/축제
## 맛집 추천
## 1일 일정 제안
## 오류 요약
```

- 맛집 검색 결과가 없으면 `데이터 없음`으로 표시한다.
- 1일 일정은 오전, 오후, 저녁 수준으로 제안한다.
- 실행 중 발생한 오류가 있으면 오류 요약에 표시한다.

### 4.6 오류 처리

API 호출과 JSON 파싱 오류는 `try-except`로 처리한다.

최소 오류 처리 정책:

- 필수 API 키 미설정
  - 설정 방법을 안내하고 즉시 종료한다.
- 지도·장소 API 실패
  - 네트워크, 인증, 쿼터 오류 등을 오류 목록에 기록한다.
  - 맛집을 `데이터 없음`으로 처리하고 리포트 생성을 계속한다.
- 맛집 검색 결과 0건
  - 빈 목록으로 처리하고 리포트 생성을 계속한다.
- LLM JSON 파싱 실패
  - JSON만 다시 출력하도록 프롬프트를 수정해 최대 1회 재시도한다.
  - 무한 재시도하지 않는다.

오류는 내부 `errors` 목록에서 관리한다.

```json
{
  "errors": [
    {
      "step": "place_search",
      "type": "AUTH_ERROR",
      "message": "HTTP 401"
    }
  ]
}
```

### 4.7 API 키 관리

- API 키를 소스 코드에 직접 작성하지 않는다.
- `.env` 또는 환경변수에서 읽는다.
- `.env`는 Git에 커밋하지 않는다.
- README, 로그, JSON, Markdown 결과 파일에 실제 키가 노출되지 않도록 한다.

환경변수 설정 예시:

```bash
# macOS/Linux
export OPENAI_API_KEY="YOUR_KEY"
```

```powershell
# Windows PowerShell
$env:OPENAI_API_KEY="YOUR_KEY"
```

API 키를 환경변수로 관리하는 이유:

- 협업이나 제출 과정에서 키가 공개되는 사고를 방지할 수 있다.
- 키를 교체해도 소스 코드를 수정할 필요가 없다.
- 과금과 쿼터가 연결된 서비스의 보안 사고를 예방할 수 있다.

### 4.8 결과 저장

- 프로그램이 `results/` 폴더를 자동으로 생성한다.
- 입력받은 여행 날짜를 파일명에 포함한다.
- 원본 JSON과 최종 Markdown 리포트를 저장한다.

원본 JSON 최소 구조:

```json
{
  "recommendation": {
    "recommended_city": "제주",
    "weather": "날씨 요약",
    "events": ["행사 후보"],
    "reason": "추천 이유"
  },
  "restaurants": [],
  "errors": []
}
```

권장 파일명:

```text
results/YYYY-MM-DD_raw.json
results/YYYY-MM-DD_travel_plan.md
```

## 5. 실행 로그 예시

```text
[1/3] 1차 추천 생성 중(LLM)...
  - recommended_city: 제주
[2/3] 맛집 검색 중(지도/장소 API)...
  - 맛집 5곳 검색 완료
[3/3] 최종 리포트 생성 중(LLM)...
  - 리포트 생성 완료

완료! results/20XX-03-15_travel_plan.md 를 확인하세요.
```

장소 검색에 실패하더라도 다음과 같이 리포트 생성을 계속한다.

```text
[2/3] 맛집 검색 중...
  - 오류: 인증 실패(401). 키 설정을 확인하세요.
  - 맛집 섹션은 '데이터 없음'으로 처리하고 계속 진행합니다.
```

## 6. 보너스 과제

### 복수 지역 추천

- `recommended_city` 대신 `recommended_cities` 배열로 2~3개 지역을 추천한다.
- 반복문으로 각 지역의 맛집을 검색한다.
- 최종 리포트에 지역별 결과를 정리한다.

### 결과 캐싱

- 같은 날짜로 다시 실행할 때 기존 원본 JSON이 있으면 API 호출을 생략한다.
- 기존 데이터를 이용해 리포트를 다시 생성하거나 기존 결과를 사용한다.
