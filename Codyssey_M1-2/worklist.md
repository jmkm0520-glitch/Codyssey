## 4. 요청을 받을 기본 서버 만들기

처음 배우는 사람의 말로:

- **쉽게 말하면:** 아직 세부 기능은 없지만, 요청을 받을 수 있는 서버의 뼈대와 공통 규칙을 만드는 단계다.
- **이어지는 흐름:** 1단계의 백엔드 폴더와 3단계의 환경 설정을 이용한다. 이후 5~11단계의 API가 이 서버에 하나씩 연결된다.
- **처음 보는 말:** `FastAPI`는 Python 서버 제작 도구, `엔드포인트`는 요청을 받는 주소, `CORS`는 허용한 웹 화면만 서버에 요청하게 하는 규칙, `Swagger UI`는 API를 브라우저에서 시험하는 화면이다.
- **끝났다는 뜻:** 서버가 실행되고 `/health`가 정상 응답하며 `/docs`에서 API 문서 화면이 열린다.

- [x] 4-1 FastAPI 서버가 시작되도록 기본 앱을 만든다. (`backend/main.py`)
- [x] 4-2 서버의 이름, 설명, 버전을 한국어로 적는다. (`0.1.0`)
- [x] 4-3 서버가 살아 있는지 확인할 주소 `/health`를 만든다. (`200`, `status=ok` 확인)
- [x] 4-4 우리 서비스의 API 주소가 모두 `/api`로 시작하게 맞춘다. (`/api` 진입점 확인)
- [x] 4-5 `.env` 같은 코드 밖의 설정을 읽고, 필요한 값이 빠졌는지 확인한다. (`backend/core/config.py`)
- [x] 4-6 접속을 허용할 화면 주소 여러 개를 `ALLOWED_ORIGINS`에 쉼표로 나누어 적을 수 있게 한다.
- [x] 4-7 내 컴퓨터의 화면과 나중에 Vercel에 올릴 화면이 서버에 요청할 수 있도록 CORS 허용 규칙을 만든다. (사전 요청 테스트 통과)
- [x] 4-8 어디서 오류가 나더라도 사용자에게 같은 형식의 안전한 한국어 안내를 돌려준다. (`ErrorResponse`)
- [x] 4-9 내 컴퓨터에서 Uvicorn으로 FastAPI 서버를 실행한다. (`127.0.0.1:8000` 실행 확인)
- [x] 4-10 브라우저에서 API를 시험할 수 있는 Swagger UI가 열리는지 확인한다. (`/docs` HTTP 200)
- [x] 4-11 API 문서에 서버가 받을 값과 돌려줄 값의 모양이 보이는지 확인한다. (OpenAPI 스키마 확인)

서버를 켜는 명령:

```bash
uvicorn backend.main:app --reload
```

브라우저에서 확인할 주소:

- 서버가 살아 있는지 확인: `http://localhost:8000/health`
- API를 직접 시험하는 화면: `http://localhost:8000/docs`

## 7. 정리한 매출 자료를 Firestore에 한꺼번에 넣기


AI에게 반드시 알려줄 내용:

- 너는 온라인 쇼핑몰의 매출을 설명하는 비서라는 역할
- 저장된 매출의 날짜 범위와 자료 개수

## 11. 질문부터 답변 저장까지 한 번에 처리하는 채팅 기능 만들기

- [x] 11-1 사용자 질문을 받는 주소 `POST /api/chat`을 만든다.

질문 하나가 처리되는 순서:

```text
사용자 질문
→ Firestore 데이터 조회 및 요약
→ 시스템 프롬프트에 요약 주입
→ OpenAI API 호출
```

이 단계가 끝났는지 확인하기:

- 성공했는지 실패했는지 화면이 판단할 수 있도록 알맞은 상태 번호와 오류 안내를 준다.
