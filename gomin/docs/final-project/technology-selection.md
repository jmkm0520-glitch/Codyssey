# 기술 스택 선정 이유

고민일기는 과제 수행 과정에서 익힌 기술과 플랫폼을 활용해 설정·학습 시간을 줄이고, AI 기능과 사용자 경험 구현에 집중하는 방향으로 기술을 선정했다. AI API 지원과 무료 플랜을 활용해 개발·운영 비용을 줄이는 점도 고려했다.

이 문서는 프로젝트 선정 당시의 경험과 판단을 정리한다. 기술 구성과 처리 흐름은 [시스템 아키텍처](requirements/architecture.md)를 참고한다.

## 배포 플랫폼 — Vercel·Render

프론트엔드는 Vercel, 백엔드는 Render를 선택했다. 두 플랫폼 모두 이전 과제에서 사용한 경험이 있어, 새로운 배포 환경을 익히거나 설정하는 데 드는 시간을 줄일 수 있다고 판단했다.

또한 두 플랫폼이 제공하는 Git 연동 빌드·자동 배포 기능을 활용하면 배포 파이프라인을 별도로 구축·관리하는 부담을 줄일 수 있다는 점을 고려했다. 배포는 플랫폼 기능을 활용하고, 기능 개발과 서비스 흐름을 완성하는 데 시간을 쓰고자 했다.

## 백엔드 프레임워크 — FastAPI

FastAPI는 과제에서 가장 많이 사용했던 백엔드 프레임워크였다. 이미 익숙한 방식으로 API와 서버 기능을 구현할 수 있어, 새로운 프레임워크를 학습하는 시간을 줄이기 위해 선택했다.

## 프론트엔드 프레임워크 — Next.js

Next.js는 프론트엔드에서 널리 사용돼 AI가 참고할 수 있는 학습 자료와 문서가 충분할 것이라고 판단했다. 바닐라 JavaScript로 화면을 구성할 때보다 AI의 구현 답변 품질이 더 좋을 것으로 기대해 선택했다.

## 텍스트 AI — 네이토

아카데미에서 네이토의 API 비용을 지원해 주기 때문에, 지원 자원을 최대한 활용해 AI 기능을 개발하고자 했다. 대화 응답, 대화 요약, 그림일기의 제목·위로 문구·이미지 프롬프트 구성에 네이토를 사용했다.

## 이미지 AI — Gemini

모리의 모습을 유지하면서 고민에 맞는 그림을 만들기 위해, 참조 이미지와 텍스트 프롬프트를 함께 입력받는 멀티모달 AI가 필요했다. 선정 당시 사용하던 네이토의 이미지 생성 기능은 이 입력 방식을 지원하지 않아 별도의 이미지 생성 모델을 검토했다.

검토한 이미지 생성 모델 중 비용이 가장 낮다고 판단한 Gemini를 선택했다. 텍스트 구성에는 지원받는 네이토를 활용하고, 참조 이미지와 프롬프트를 함께 처리하는 이미지 생성에는 Gemini를 사용하는 방식으로 역할을 나눴다.

## 데이터베이스·파일 저장소 — Supabase

Supabase는 무료 플랜의 제공 범위가 비교적 넉넉하고, 데이터베이스와 파일 스토리지를 함께 제공한다는 점을 고려해 선택했다.

회원·대화·요약·컬렉션 데이터는 PostgreSQL에, 생성된 이미지는 Storage에 보관한다. 데이터베이스와 스토리지 서버를 각각 준비하고 운영하는 대신 한 플랫폼에서 관리해 설정과 운영에 드는 비용을 줄이고자 했다.
