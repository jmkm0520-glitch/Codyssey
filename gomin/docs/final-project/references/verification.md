# 고민일기 검증·배포 결과

## 배포 서비스

[고민일기](https://www.gomin.today)는 Vercel의 프론트엔드, Render의 백엔드, Supabase의 DB·Storage로 구성한다.

통합 테스트와 사용자 테스트는 배포 환경에서 **대화 → 요약 → 그림 생성 → 저장 → 재조회**를 수행하며 확인했다.

## 기존 검증 기록

다음은 [털어놓기 MVP 검증 기록](../../engineering/talk-mvp-qa.md)에 남아 있는 결과다. 문서 작성 중 새로 실행한 테스트 결과가 아니다.

| 검증 | 기록된 결과 | 확인 범위 |
| --- | --- | --- |
| 백엔드 단위 테스트 | 152개 통과 | API, AI 어댑터, 정상·실패 응답과 비소유 요청. 저장소·제공자 일부는 모의 환경 사용 |
| 대화 SQL | 임시 PostgreSQL에서 8개 통과 | 소유권·순서·요약 버전·확정과 실행 제약 |
| 기존 DB 회귀 검증 | 임시 PostgreSQL에서 16개 통과 | 대화·컬렉션의 기존 데이터 제약 |
| 로컬 Supabase | SQL 적용·RPC 검증 통과 | 저장·타인 접근 거부·복원·재요약·확정. 검증 데이터는 트랜잭션 롤백 |
| 이미지 연결·재생성 회귀 | 프론트엔드 테스트 53개와 lint·typecheck 통과 | 요약 확정과 이미지 화면 연결, 재생성 중·실패·성공의 상태 처리 |
| Chrome 화면 QA | 4개 화면 크기 통과 | 모의 API에서 PC·모바일 이용 흐름과 작은 화면 조작 |

Chrome 검증 화면 크기는 1440×900, 390×844, 320×568, 667×375다. 모의 API 검증은 실제 AI 품질이나 외부 서비스 통합 결과를 대신하지 않는다.

기존 기록에는 공개 문서 테스트의 Windows 심볼릭 링크 권한 오류도 남아 있다. 이후 기록된 특정 회귀 테스트 통과와 해당 오류를 해결했다는 판단은 구분한다.

## 검증 범위 구분

| 항목 | 근거가 있는 결과 |
| --- | --- |
| 배포 환경 전체 이용 흐름 | 담당자가 직접 확인 |
| 배포 환경 사용자 테스트 | 실사용자 5명, 대면 피드백 수집 |
| 자동·격리 검증 | 기존 QA 문서에 기록된 범위에서 통과 |
| 실제 AI 응답·그림의 품질 | 사용자의 불편 의견과 프롬프트 수정 이력 존재. 수정 후 품질 평가는 기록하지 않음 |

실기기 한글 입력·가상 키보드·Safari·동시 DB 연결 경합·가용성·응답 시간은 확인된 결과가 없어 통과 항목에 넣지 않았다.

## 운영 모니터링

프로젝트 운영 문서에는 UptimeRobot이 백엔드 `/api/v1/health`를 5분 간격으로 확인하고 이메일로 알린다. 이 상태 API는 서버 응답을 확인하며 DB·Storage·메일·로그인의 정상 동작까지 보장하지 않는다.
