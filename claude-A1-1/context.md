# 리스트 (List)

순서가 있는 여러 개의 데이터를 하나의 변수에 담아 관리하는 자료구조입니다.

> 비유: 번호가 매겨진 사물함 줄. 1번 칸, 2번 칸, 3번 칸... 순서대로 물건을 넣어두고, 번호로 원하는 칸을 찾아 꺼낼 수 있다.

```python
prompts = ["회의록 요약", "AI 뉴스 요약", "광고 영상 생성"]
print(prompts[0])  # 1번 칸(0번 인덱스) 꺼내기 → 회의록 요약
```

# 딕셔너리 (Dictionary)

키(key)와 값(value)을 한 쌍으로 묶어서 저장하는 자료구조입니다.

> 비유: 영어사전. "단어(키)"를 찾아 펼치면 그에 대응하는 "뜻(값)"이 바로 나온다.

```python
prompt = {"title": "회의록 요약", "category": "텍스트 생성", "favorite": True}
print(prompt["title"])  # "title"이라는 단어를 찾으면 → 회의록 요약
```

# 중첩 구조 (리스트 + 딕셔너리)

## 리스트 안에 딕셔너리가 있는 경우

여러 개의 사물함(리스트) 각 칸 안에, 이름표가 붙은 서랍(딕셔너리)이 하나씩 들어있는 구조입니다. 우리 프로젝트의 `prompts`가 정확히 이 형태입니다.

> 비유: 사물함 줄(리스트) 각 칸을 열면, 그 안에 "제목", "내용", "카테고리" 라벨이 붙은 서랍(딕셔너리)이 들어있다.

```python
prompts = [
    {"title": "회의록 요약", "category": "텍스트 생성"},
    {"title": "AI 뉴스 요약", "category": "자동화"}
]
print(prompts[0]["title"])  # 0번 칸을 열고 → "title" 서랍을 꺼냄 → 회의록 요약
```

## 딕셔너리 안에 리스트가 있는 경우

이름표가 붙은 서랍(딕셔너리) 하나를 열었더니, 그 안에 물건이 여러 개 나란히 든 상자(리스트)가 들어있는 구조입니다.

> 비유: "태그" 라벨이 붙은 서랍을 열었더니, 그 안에 태그 스티커 여러 장이 순서대로 나란히 들어있다.

```python
prompt = {
    "title": "회의록 요약",
    "tags": ["회의", "요약", "업무"]
}
print(prompt["tags"][0])  # "tags" 서랍을 열고 → 0번째 스티커를 꺼냄 → 회의
```

# 브랜치 (Branch)

현재 코드 상태에서 갈라져 나온 독립적인 작업 흐름으로, 원본(main)에 영향을 주지 않고 커밋을 쌓을 수 있는 공간입니다.

브랜치를 만드는 이유는 불안정한 코드가 main에 섞이지 않도록 격리해서 작업하고, 완성되면 병합(merge)하기 위해서입니다.

# 5-1에서 배운 개념

## `.strip()` — 양옆 공백을 잘라내기

사용자가 실수로 스페이스를 앞뒤에 넣고 입력해도 깔끔하게 만들어주는 메서드입니다.

```python
input_value = "  안녕  "
print(input_value.strip())  # "안녕" (양쪽 공백만 사라짐)
```

## `while` 반복문 — "이 조건이 참인 동안" 계속 돌기

`for`처럼 몇 번 돌지 정해놓은 게 아니라, 조건이 거짓이 될 때까지 반복합니다.

```python
count = 0
while count < 3:      # count가 3보다 작은 동안 계속 반복
    print(count)
    count += 1
# 0, 1, 2 출력하고 count가 3이 되면 조건이 거짓이라 멈춤
```

## 빈 문자열의 논리값 — "비어있으면 거짓"

사람이 "아무것도 안 썼다"고 느끼는 걸 파이썬도 `False`로 인식합니다.

```python
title = ""
print(bool(title))       # False (아무 내용 없음)
title = "제목"
print(bool(title))        # True (내용 있음)
```

그래서 `while not title:`은 "제목에 아무것도 없는 동안 계속 다시 물어봐"라는 뜻이 됩니다.

## `.isdigit()` — 숫자로만 이루어졌는지 검사하는 문지기

사용자가 메뉴 번호 대신 글자를 입력해도 프로그램이 안 죽게 미리 걸러주는 역할입니다.

```python
"3".isdigit()       # True  → 숫자니까 통과
"삼".isdigit()       # False → 숫자가 아니니까 막힘
"3.5".isdigit()      # False → 점(.)이 섞여있어서 숫자로만 이루어진 게 아님
```

## `list.append()` — 리스트 끝에 새 물건 하나 얹기

기존 리스트는 그대로 두고, 맨 뒤에 딱 하나만 추가합니다.

```python
prompts = ["회의록 요약"]
prompts.append("AI 뉴스 요약")
print(prompts)   # ["회의록 요약", "AI 뉴스 요약"] ← 뒤에 하나 더 붙음
```

# 5-2에서 배운 개념

## `enumerate()` — 순서대로 꺼낼 때 번호표도 같이 붙여주기

리스트를 그냥 `for`로 돌리면 값만 나오고 몇 번째인지 알 수 없습니다. `enumerate()`는 값과 순서(번호)를 짝지어서 동시에 꺼내줍니다.

```python
prompts = ["회의록 요약", "AI 뉴스 요약", "광고 영상 생성"]

for i, title in enumerate(prompts, start=1):
    print(i, title)
# 1 회의록 요약
# 2 AI 뉴스 요약
# 3 광고 영상 생성
```

`start=1`을 주지 않으면 번호가 0부터 시작합니다. 사람이 보기 편하게 1번부터 세고 싶을 때 `start=1`을 붙입니다.

## 조건부 표현식(삼항 연산자) — "조건 맞으면 A, 아니면 B"를 한 줄로

일반 `if`/`else` 여러 줄을 한 줄로 압축한 문법입니다. **가운데 조건부터** 읽어야 헷갈리지 않습니다.

```python
# 긴 버전
if favorite:
    star = "⭐"
else:
    star = ""

# 짧은 버전 (결과는 동일)
star = "⭐" if favorite else ""
```

| `favorite` 값 | 조건 결과 | `star`에 들어가는 값 |
|---|---|---|
| `True` | 맞음 | `"⭐"` |
| `False` | 틀림 | `""` |

## 빈 리스트의 논리값 — 텅 비어있으면 "없음"으로 취급

빈 문자열([[5-1에서 배운 개념]] 참고)처럼, 빈 리스트 `[]`도 `False`로 취급됩니다.

```python
prompts = []
print(bool(prompts))         # False (아무것도 없음)

prompts = ["회의록 요약"]
print(bool(prompts))         # True (항목이 있음)
```

그래서 `if not prompts:`는 "prompts에 항목이 하나도 없다면"이라는 뜻이 됩니다.

## 조기 반환(early return) — 조건에 걸리면 함수를 그 자리에서 바로 끝내기

식당에서 "재료가 다 떨어졌어요"라는 말을 들으면 자리에 앉지 않고 바로 돌아가는 것처럼, 특정 조건을 만나면 함수의 나머지 코드는 실행하지 않고 즉시 끝내버리는 것입니다.

```python
def show_list(prompts):
    if not prompts:
        print("등록된 프롬프트가 없습니다.")
        return          # 여기서 함수가 즉시 끝남 (아래 for문은 실행 안 됨)

    for i, p in enumerate(prompts, start=1):
        ...
```

`prompts`가 비어있으면 안내 메시지만 찍고 함수를 끝내서, "이 아래 코드는 리스트가 비어있지 않을 때만 의미가 있다"는 의도가 코드만 봐도 명확해집니다. 이런 패턴을 **가드 절(guard clause)**이라고 부릅니다.

# 5-3에서 배운 개념

`show_by_category()`는 [[5-2에서 배운 개념]]의 `enumerate()`, 조건부 표현식, 빈 리스트의 논리값, 조기 반환을 그대로 재사용합니다. 새로 등장한 개념은 리스트 컴프리헨션 하나입니다.

## 리스트 컴프리헨션 — 조건에 맞는 것만 골라 새 리스트 만들기

과일 바구니에서 "사과만 골라내는" 것처럼, 원본 리스트를 돌면서 조건에 맞는 것만 뽑아 새 리스트를 한 줄로 만드는 문법입니다.

```python
filtered = [p for p in prompts if p["category"] == category]
```

**풀어서 쓰면 (같은 동작)**

```python
filtered = []
for p in prompts:
    if p["category"] == category:
        filtered.append(p)
```

**예시로 따라가보기** (`category`가 `"텍스트 생성"`일 때)

| `prompts` 안의 항목 | 카테고리 일치? | `filtered`에 들어감? |
|---|---|---|
| 회의록 요약 (텍스트 생성) | O | ✅ |
| AI 뉴스 요약 (자동화) | X | ❌ |
| 광고 영상 생성 (영상 생성) | X | ❌ |

결과: `filtered = [회의록 요약]`

`for`문 여러 줄로 "새 리스트 만들면서 필터링하기"를 `[결과 for 항목 in 원본 if 조건]` 한 줄로 압축한 파이썬만의 문법이며, [[5-1에서 배운 개념]]의 `list.append()`를 매번 안 써도 되는 게 장점입니다.

# 5-4에서 배운 개념

`search_prompt()`는 [[5-1에서 배운 개념]]의 `.strip()`·`while` 반복문·빈 문자열의 논리값, [[5-3에서 배운 개념]]의 리스트 컴프리헨션·조기 반환을 그대로 재사용합니다. 새로 등장한 개념은 `in` 연산자 하나입니다.

## `in` 연산자 — "이 안에 포함되어 있나?"를 물어보는 연산자

친구한테 "그 문장에 '사과'라는 말 들어있어?"라고 물어보면 "응"/"아니"로 답하는 것처럼, `in`은 왼쪽 값이 오른쪽 값(문자열, 리스트 등) 안에 포함되어 있는지 확인해서 `True`/`False`를 돌려줍니다.

```python
"사과" in "나는 사과를 좋아해"     # True  → "사과"라는 글자가 포함되어 있음
"바나나" in "나는 사과를 좋아해"   # False → "바나나"라는 글자는 없음
```

완전히 같아야 하는 게 아니라, **일부만 포함되어도 True**입니다.

```python
"회의" in "회의록 요약"    # True (부분적으로 포함됨)
"요약본" in "회의록 요약"  # False (연속된 글자로는 없음)
```

**우리 코드에서의 사용 (`main.py:115`)**

```python
if keyword in p["title"] or keyword in p["content"]:
```

`keyword`가 제목에 포함되어 있거나, `or`로 연결되어 내용에 포함되어 있으면 조건이 참이 됩니다. `or`는 둘 중 하나만 참이어도 전체가 참이 되는 연산자라서, "제목엔 없어도 내용에 있으면" 검색되도록 해줍니다.

참고로 `in`은 리스트에도 똑같이 쓸 수 있습니다.

```python
"사과" in ["사과", "바나나", "포도"]   # True (리스트 안에 그 항목이 있는지)
```

# 5-5에서 배운 개념

`show_detail()`은 [[5-1에서 배운 개념]]의 `.strip()`, [[5-2에서 배운 개념]]의 조건부 표현식·조기 반환을 재사용하고, 이미 만든 `show_list()` 함수를 그대로 호출해서 재사용합니다. 새로 등장한 개념은 **단락 평가(short-circuit evaluation)**입니다.

## 단락 평가 — 앞에서 답이 정해지면 뒤는 확인하지 않는다

```python
if not number.isdigit() or not (1 <= int(number) <= len(prompts)):
    print("잘못된 번호입니다.")
    return
```

`or`로 연결된 조건은 **왼쪽부터 순서대로** 검사하는데, 왼쪽이 이미 `True`면 오른쪽은 아예 확인하지 않고 전체를 `True`로 확정해버립니다. 이걸 단락 평가라고 부릅니다.

```python
number = "가나다"

not number.isdigit()                    # True (숫자가 아니므로)
# or 왼쪽이 이미 True이므로,
# 오른쪽의 int(number)는 실행되지 않고 넘어감
```

**이게 왜 중요한가**: 만약 `number`가 `"가나다"`인 상태에서 `int(number)`를 실행하면 파이썬은 에러를 내며 프로그램을 멈춰버립니다. 그런데 `not number.isdigit()`이 먼저 `True`로 판정되면, 단락 평가 덕분에 위험한 `int(number)` 부분은 아예 실행되지 않고 건너뛰어져서 안전합니다. 그래서 "숫자인지 먼저 검사 → 그다음에 범위 검사"처럼 **앞에 안전장치가 되는 조건을 배치하는 순서**가 중요합니다.

```python
number = "1"

not number.isdigit()                     # False (숫자이므로)
# or 왼쪽이 False이므로, 이번엔 오른쪽도 실제로 검사함
not (1 <= int(number) <= len(prompts))   # 범위 안이면 False
# 둘 다 False이므로 전체 조건은 False → "잘못된 번호"가 아님
```

# 5-6에서 배운 개념

`toggle_favorite()`과 `show_favorites()`는 [[5-5에서 배운 개념]]의 단락 평가, [[5-3에서 배운 개념]]의 리스트 컴프리헨션, [[5-2에서 배운 개념]]의 조건부 표현식·조기 반환을 모두 재사용합니다. 새로 등장한 개념은 **토글(현재 값을 `not`으로 뒤집기)** 패턴입니다.

## 토글(toggle) — 값을 현재 상태의 반대로 뒤집기

전등 스위치처럼, 누를 때마다 켜짐↔꺼짐이 반복되는 동작입니다.

```python
p["favorite"] = not p["favorite"]
```

오른쪽의 `p["favorite"]`(현재 값)를 먼저 읽고, `not`으로 뒤집은 다음, 그 결과를 다시 왼쪽의 `p["favorite"]`에 저장합니다.

| 실행 전 `p["favorite"]` | `not p["favorite"]` | 실행 후 `p["favorite"]` |
|---|---|---|
| `True` | `False` | `False` |
| `False` | `True` | `True` |

즉 `if`문으로 "참이면 거짓으로, 거짓이면 참으로" 바꾸는 걸 한 줄로 압축한 것과 같습니다.

```python
# 풀어서 쓰면 (같은 동작)
if p["favorite"]:
    p["favorite"] = False
else:
    p["favorite"] = True
```

`toggle_favorite()`을 호출할 때마다 이 한 줄이 실행되기 때문에, 같은 번호를 두 번 고르면 등록 → 해제로, 세 번 고르면 다시 해제 → 등록으로 계속 반전됩니다.
